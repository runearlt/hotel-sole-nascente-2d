# Hotel case and actor conversations

The hotel exercise follows `1. EN - Case.doc` (sections 1–4.1): **78 rooms**, prices in **DKK**, and Table 3 customer-group demand in **room-nights**. The bakery and winery are separately labelled, euro-priced game extensions; their quantities do not come from the original case. The source document's `TENTATIVE SOLUTIONS` section is excluded from actor context.

Students choose **Guided** or **Ask your own questions** at the start. The main route covers hotel questions 4.1.1–4.1.4 plus supporting TR/MR practice; bakery, winery and street practice are optional and never required for hotel completion. Written reasoning is saved for instructor review. Guided questions are in `public/app.js` (`Q`). The free-question role cards are in `public/free-agents.js`; edit `instruction`, `facts`, `match`, `say`, `solutionBoundary` and `scopePrompt` to tune each actor. Curated original-case background for the model is in `server/case-facts.js`. The hotel calculations and validation are in `public/case-hotel.js`.

Calculation and written-answer drafts are stored locally as the student types. Hints, notebook visits and reloads preserve unfinished work. Saved hotel steps can be reopened with the review buttons in the workspace; invalid revisions do not overwrite the last accepted answer. Exported JSON includes saved answers, drafts and working notes.

With `OPENAI_API_KEY` set **on the server**, the free-question mode calls `POST /api/actor`. `server/actor-api.js` selects an approved reply for the current question and asks the OpenAI Responses API to phrase that content in the character's voice. It sends previous student questions for context but never trusts client-supplied prior answers as case evidence. Student messages are treated as questions. Full-solution requests are blocked before the API call; factual equation requests are allowed. Incomplete replies, unexpected numbers, missing required quantities and obvious worked solutions fall back to approved facts. Model output is still nondeterministic, and these checks do not guarantee semantic correctness, so a small real-student pilot remains necessary. Without a key, the endpoint replies using conversational, deterministic facts, including group-specific answers, two-part questions and short follow-ups. The key must never be put in `public/` or committed to GitHub.

Local development: `npm ci`, then `npm start`. Open `http://localhost:8174`. To test model replies, supply `OPENAI_API_KEY` as a server environment variable. Run `npm test`, `npm run test:student`, and `npm run test:simulation`. The browser tests cover Guided and free-question modes at desktop and phone sizes. The 100 scripted playthroughs test the route and deliberately incorrect answers; they are not real students.

On Render, this bot needs a **Node web service** using `npm ci --omit=dev` and `npm start`, with `OPENAI_API_KEY` set as a secret environment variable. An existing Render static site cannot serve `/api/actor`; if only static hosting is available, the game uses deterministic fact replies. `render.yaml` describes a Node web service for a new deployment. Configure the model with `OPENAI_MODEL` if desired; the default is `gpt-5-mini`.
