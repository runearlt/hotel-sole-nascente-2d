# Hotel Sole Nascente: 3D version

This branch replaces the active flat town and room renderers with self-hosted Three.js scenes. The economics and server actor policy remain in their existing modules. The scenario remains the 80-room EUR demonstration; the bakery and winery remain optional extensions.

## Running and building

Use `npm ci` for development, then `npm run start:offline` for an offline preview or `npm start` for the configured production server. The production server does not require a build step: `public/vendor/three-bundle.js` is committed. After changing the engine exports or pinned Three.js dependency, run `npm run build:3d` and commit the generated bundle and licence together. Production installs can omit development dependencies.

The implementation is divided into `world-layout.js` (metre-based bounds, collisions and route finding), `world-art.js` (procedural geometry, materials and characters), and `world3d.js` (rendering, camera, input, interactions and resource disposal). The existing app owns conversations, exercises, progress and storage. Scene instances survive panel rerenders and are disposed when changing location. Legacy saved positions migrate to valid spawn points while retaining the student's investigation.

## Controls and accessibility

Move with WASD or arrow keys; drag the scene to rotate the camera and scroll to zoom. Click the floor to walk, or click a person or entrance to approach it. Press E or Enter near an interaction. Mobile users have movement buttons and can drag the scene. Named location and staff buttons provide direct access without requiring navigation skills. Workspace and Notebook remain available from the header. Keyboard input in forms does not move the player.

The opening screen renders the actual town behind a blurred overlay. Starting resumes saved progress. If WebGL 2 is unavailable, a visible explanation is shown and the location buttons, conversations, Workspace and Notebook remain usable.

## Asset sources and licences

All architecture, furniture, vegetation, human geometry, animations, signs and material textures in the new scenes are original procedural assets generated by this project's `world-art.js`. No downloaded models, photographs, textures or character packs are used. Sign lettering uses locally available system fonts through canvas rendering.

The rendering engine is Three.js 0.187.0, MIT licensed: https://github.com/mrdoob/three.js/tree/r187 . The bundled engine also includes the project's BufferGeometryUtils geometry-merging helper. Its full licence is shipped in `public/vendor/THREE-LICENSE.txt`. esbuild 0.28.2 is a development build tool: https://github.com/evanw/esbuild . Dependency versions are pinned in package-lock.json.

## Performance and verification

The engine is loaded dynamically and served locally. Static geometry is merged by material. Desktop pixel ratio is capped at 1.6, mobile at 1.25; mobile disables dynamic shadows. GPU geometry, textures, controls, observers and rendering loops are released when leaving a scene. Hardware acceleration and WebGL 2 are required for the 3D visuals. The environment is architectural, stylised 3D rather than photorealistic; performance on every student device cannot be guaranteed.

Run `npm run test:offline` for unit/HTTP checks, desktop/mobile exercise journeys and 100 synthetic student journeys using a mocked provider. Run `npm run test:3d` for actual WebGL rendering, full-viewport sizing, keyboard and touch movement, camera rotation, approach interactions, scene reuse, saved progress, optional interiors and unsupported-WebGL behaviour. CI runs the same 100 seeded profiles in five parallel batches of 20, using SIMULATION_OFFSET values 0, 20, 40, 60 and 80. OFFLINE_SUITE=core runs the unit and desktop/mobile journeys; OFFLINE_SUITE=simulation runs the selected profile batch. The default npm run test:offline still runs the complete suite and all 100 profiles. This avoids the single-runner time limit without removing any checks. These tests do not spend API credit and do not prove live provider availability. Set WORLD3D_URL to verify a deployed site; actor requests in that browser suite are intercepted with local responses.

Render should serve the completed `3d-version` branch with its existing start command and existing environment configuration. Do not put API keys in client code or asset files. Publication and deployment are separate from local verification; the deployed commit must be checked before describing the version as live.
